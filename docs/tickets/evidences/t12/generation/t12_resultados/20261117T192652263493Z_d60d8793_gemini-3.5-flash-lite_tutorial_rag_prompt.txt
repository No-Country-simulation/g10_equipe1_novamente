## Exemplo de consulta
Um sistema de treinamento pode consultar GET /cursos/42 para obter informações de um curso. Se o curso existir e a pessoa tiver acesso, o servidor pode devolver 200 e um objeto JSON. Se o curso não existir, pode devolver 404. Se a identidade não tiver permissão, pode devolver 403 conforme as regras definidas.

## Exemplo de criação
Um sistema pode enviar POST /cursos com um corpo JSON contendo título e descrição. Quando um recurso é criado com sucesso, o servidor pode responder 201. Antes de criar o registro, o backend valida os dados e confere se o usuário tem permissão.

## Códigos de sucesso
200 (OK) sinaliza sucesso na operação. 201 (Created) informa a criação de um recurso. 204 (No Content) sinaliza sucesso sem corpo de resposta. O significado exato precisa ser interpretado juntamente com o método e a documentação da API.

## Códigos relacionados a requisições inválidas
400 (Bad Request) sinaliza problema na requisição. 401 (Unauthorized) indica que faltam credenciais válidas de autenticação. 403 (Forbidden) indica que o servidor compreendeu a requisição, mas recusa sua execução. 404 (Not Found) informa que o recurso não foi encontrado.

## Representações JSON
JSON pode representar objetos com pares chave/valor, arrays, textos, números, booleanos e null. O cabeçalho Content-Type: application/json descreve o formato enviado. HTTP não obriga que toda resposta seja JSON. Uma API pode escolher outra representação e deve documentá-la.
